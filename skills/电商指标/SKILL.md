# 电商指标规范

## 1. 指标定义（统一口径）

| 指标 | 计算方法 | 说明 |
|---|---|---|
| 销售额（GMV） | 所有订单的 单价 × 数量 之和 | **包含**已退货订单 |
| 净销售额 | 未退货订单的销售额之和 | 扣除退货后真正留下的销售额；比较品类“贡献”时优先用它 |
| 订单数 | 订单行数（清洗后） | |
| 退货率（按订单） | 退货订单数 ÷ 订单数 | 默认用这个 |
| 退货金额率 | 退货订单的销售额 ÷ 销售额 | 大额订单退货多时，与按订单的退货率差别会很大 |
| 客单价 | 销售额 ÷ 订单数 | |
| 广告投入产出比（ROAS） | 销售额 ÷ 广告花费 | 越高越好 |
| ACOS | 广告花费 ÷ 销售额 | 越低越好，是 ROAS 的倒数 |
| 占比 | 某一组 ÷ 合计 | |

数据里没有成本、毛利字段时，**不能**计算利润或利润率，要明确说明“无法从数据中得出”。

## 2. 计算规则

1. **所有指标都在代码里算出来**，放进 `result["metrics"]` 或 `result["tables"]`。包括“差多少”“是几倍”“占比多少”这类比较，也要在代码里算好，**不要在报告里心算**。
2. 比较品类、店铺的贡献时，**同时给出销售额和净销售额**，并说明两者排名是否一致。
3. 订单数少于 30 的分组，比率波动大，在表格里加一列“样本是否充足”，报告里要提醒。

## 3. 不要自行设计综合评分

- 用户没有要求打分时，**不要**自己设定权重、计算“综合得分”“优先级分”之类的指标；
- 回答“哪个最值得投入”这类问题时，用一张表**分别列出**规模（净销售额）、质量（退货率）、效率（ROAS）等指标，再用文字说明各候选的优势和短板，以及取舍取决于什么目标（例如“追求规模选 A，追求低退货选 B”）；
- 如果用户明确要求综合评分，必须写明权重是怎么定的，并提醒结论对权重敏感。

## 写报告时

- 第一次出现某个指标时，用括号写明它的定义，例如“退货率（退货订单数 ÷ 订单数）”；
- 写明用的是销售额还是净销售额；
- 引用的差距、倍数、占比，必须是步骤结果里已经算好的数字。
